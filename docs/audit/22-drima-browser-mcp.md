- Summary: A Python package (drima-browser-mcp 0.1.0) that starts one persistent, visible browser through Playwright, Firefox by default and Chromium optionally, in a dedicated profile directory, and exposes 14 browser tools over a loopback HTTP service with a bearer token, plus a stdio proxy and a diagnostic CLI. It is not a browser extension and does not read the user's existing Firefox profile. Tab IDs are stable within the service process and every tool call is serialized through one lock.

## Architecture

- Language and SDK: Python 3.12 or later; dependencies are the MCP Python SDK (mcp 2.2 to 3), playwright 1.62.0, uvicorn, httpx2 ([pyproject.toml#L7-L13](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/pyproject.toml#L7-L13)). The server is built with the SDK's MCPServer class ([server.py#L9-L11](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/server.py#L9-L11), [server.py#L45-L53](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/server.py#L45-L53)).
- Transport, every hop: an MCP client starts `drima-browser stdio`, which runs an MCP stdio server and forwards each list and call ([cli.py#L52-L82](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/cli.py#L52-L82), [cli.py#L133-L134](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/cli.py#L133-L134)). Each forwarded call opens a streamable HTTP client to http://127.0.0.1:8766/mcp with a bearer header read from the token file ([cli.py#L39-L49](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/cli.py#L39-L49)). The service is started by `drima-browser serve`: uvicorn binds 127.0.0.1 and serves the MCP app in stateless mode with JSON responses, wrapped by the LocalAuth check ([cli.py#L122-L132](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/cli.py#L122-L132), [cli.py#L125-L125](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/cli.py#L125-L125)). Default port 8766 ([cli.py#L110-L110](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/cli.py#L110-L110)). The README describes the same path ([README.md#L131-L134](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/README.md#L131-L134)).
- Browser side: Playwright persistent context. The engine is chosen by name: `playwright.firefox` by default, or `playwright.chromium` with channel chromium and sandbox enabled ([browser.py#L125-L137](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/browser.py#L125-L137)). The browser is launched headed unless `--headless` is given ([browser.py#L129-L131](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/browser.py#L129-L131)). This repository contains no WebExtension, Marionette, WebDriver BiDi or CDP code; the protocol Playwright uses internally is not in the checkout and was not reviewed.
- Claude or LLM sidebar UI: none. The repository has no extension manifest and no UI ([STATUS.md#L3-L3](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/STATUS.md#L3-L3)).

## Permission boundaries

- Manifest permissions: none. The repository has no browser extension and no manifest file (tracked tree listing; [STATUS.md#L3-L3](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/STATUS.md#L3-L3)).
- Host permissions: none. Navigation is limited by the public URL rule to http and https with a host and no user name, plus the exact about:blank ([browser.py#L57-L64](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/browser.py#L57-L64)). The browser can reach any such host the user's network allows.
- Per-tab or per-site grant: none enforced. Any authenticated client can list, focus, close, read, act on and evaluate script in any tab of the dedicated profile; the code has no site allowlist and no approval step ([server.py#L55-L67](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/server.py#L55-L67), [server.py#L166-L172](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/server.py#L166-L172)). Tab IDs are 10 random hex characters per page ([browser.py#L153-L158](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/browser.py#L153-L158)).
- Authentication: client to service: a bearer token. The service creates a 32-byte URL-safe token on first `serve` with exclusive create and mode 0600 in the data directory ([cli.py#L29-L36](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/cli.py#L29-L36), [cli.py#L127-L127](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/cli.py#L127-L127)). LocalAuth rejects every HTTP request that carries an Origin header or whose Authorization header differs from the expected bearer value, compared with hmac.compare_digest ([server.py#L16-L34](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/server.py#L16-L34)). Bind address: 127.0.0.1 only ([cli.py#L126-L131](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/cli.py#L126-L131)). The stdio proxy and the diagnostic CLI read the same token file ([cli.py#L39-L49](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/cli.py#L39-L49)). No TLS. The SDK's own host validation is not configured in this code (see Claimed but not verified). Token storage: data directory, default ~/.local/share/drima-browser ([cli.py#L23-L26](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/cli.py#L23-L26)).
- Sensitive-action gating: none in code. No confirmation, redaction on results, deny list or audit log. Limits that exist: uploads are capped at 10 files and 25 MiB each ([server.py#L131-L147](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/server.py#L131-L147)); a batch stops at the first error and reports completed actions with outcome unknown, and nothing retries ([browser.py#L273-L316](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/browser.py#L273-L316)); the proxy never retries a failed network call ([cli.py#L56-L73](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/cli.py#L56-L73)); network event metadata keeps only scheme, host and path ([browser.py#L67-L70](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/src/drima_browser/browser.py#L67-L70)). ## Firefox implementation notes

- Every browser-driving tool (22-F01 through 22-F14, 22-F18 through 22-F21) depends on Playwright launching its own Firefox or Chromium with a separate persistent profile. None of this runs in the user's stable Firefox profile or as a signed WebExtension, so each is unavailable there. The README says the user's existing Firefox profile is not imported or read ([README.md#L41-L42](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/README.md#L41-L42)), which is the same point.
- Firefox-specific code is absent: no CDP, Marionette or WebDriver BiDi call is written in this repository. The protocol used by Playwright's Firefox launch is inside Playwright and was not inspected.
- The service and stdio proxy (22-F15 to 22-F17) are a loopback HTTP and bearer-token design that a WebExtension cannot host; a stable-Firefox companion would replace them with a native messaging host with its own manifest for the add-on id.
- The URL rule and log redaction (22-F21) are plain logic and could be reused in an extension unchanged.
- The Linux-only headed-window hiding (22-F20) and systemd installer (22-F22) have no Windows or stable-Firefox equivalent in this repository.
- The separate Firefox extension project named in README and STATUS ([README.md#L178-L180](https://github.com/Drima-code/drima-browser-mcp/blob/b734395f586b9e7a3ed40c72a3c1aa4d5ad7cb7b/README.md#L178-L180)) is not in this checkout, so nothing here shows how it handles Firefox-native APIs.
