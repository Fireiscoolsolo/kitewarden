- Summary: Open Browser Control is an npm package: a Node MCP server (hand-written JSON-RPC over stdio, no MCP SDK) that relays tool calls over a local WebSocket bridge to a browser extension. The extension acts in the user's real browser: on Firefox through the WebExtensions scripting API in the page's MAIN world, on Chrome through the DevTools protocol. The MCP server registers 18 browser tools; the bridge has no authentication and binds all interfaces, and the add-on has no per-site or per-tab grant beyond the session tab scoping described below.

## Architecture

Hops from the MCP client to the page:

1. MCP client to MCP server: stdio, newline-delimited JSON-RPC; the server answers initialize with a fixed protocolVersion 2024-11-05, tools/list and tools/call ([mcp-server.js#L454-L474](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/bridge-server/mcp-server.js#L454-L474), [mcp-server.js#L476-L531](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/bridge-server/mcp-server.js#L476-L531), [mcp-server.js#L546-L566](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/bridge-server/mcp-server.js#L546-L566)).
2. MCP server to bridge: the server connects as a WebSocket client to ws://localhost with BRIDGE_PORT (default 9334) ([mcp-server.js#L22](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/bridge-server/mcp-server.js#L22), [mcp-server.js#L49-L50](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/bridge-server/mcp-server.js#L49-L50)). If nothing answers on that port it starts the bridge itself as a detached child process ([mcp-server.js#L178-L197](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/bridge-server/mcp-server.js#L178-L197)).
3. Bridge: a WebSocket server created with only a port, so it listens on all interfaces; it routes messages between one extension connection and any number of agent connections by session id ([server.js#L107](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/bridge-server/server.js#L107), [server.js#L221-L254](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/bridge-server/server.js#L221-L254)).
4. Bridge to extension: the extension connects to ws://localhost with its port and sends an event "connected" with its browser and instanceId as the first message ([websocket-bridge.ts#L171](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/bridge/websocket-bridge.ts#L171), [websocket-bridge.ts#L180-L185](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/bridge/websocket-bridge.ts#L180-L185)).
5. Firefox background: MV3 background scripts; each action is dispatched to the session's tab ([background.ts#L309-L355](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/firefox/background.ts#L309-L355), [background.ts#L575-L598](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/firefox/background.ts#L575-L598)).
6. Firefox page work: runInPage calls scripting.executeScript with world MAIN, so page JavaScript and DOM are used directly ([browser-actions.ts#L57-L73](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/firefox/actions/browser-actions.ts#L57-L73)). Content scripts ([content-script.ts#L135-L190](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/content/content-script.ts#L135-L190)) answer a small set of runtime messages.

Language and SDK: Node.js CommonJS with the ws package ([mcp-server.js#L13](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/bridge-server/mcp-server.js#L13), [server.js#L20](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/bridge-server/server.js#L20)). Browser side: a Firefox build (MV3, background scripts, sidebar_action, scripting and webNavigation permissions, strict_min_version 128.0; [manifest.json#L2](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/firefox/manifest.json#L2), [manifest.json#L9](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/firefox/manifest.json#L9), [manifest.json#L12-L25](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/firefox/manifest.json#L12-L25)) and a Chrome build with the debugger permission that drives the page through the DevTools protocol ([manifest.json#L6-L19](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/manifest.json#L6-L19), [browser-actions.ts#L28-L58](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/actions/browser-actions.ts#L28-L58)).

## Firefox implementation notes

- Works on stable Firefox with an MV3 background and the scripting API in the MAIN world ([browser-actions.ts#L57-L73](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/firefox/actions/browser-actions.ts#L57-L73)). Keep the MAIN world for page JavaScript and element reads; a Firefox companion with a different execution model would need its own page access path.
- The bridge is a WebSocket on localhost that the extension reaches from the background. A stable-Firefox companion would not need this transport if it talks to the MCP side through native messaging instead, which removes the open bridge port described above.
- tabs.captureTab (Firefox) is used for rect and full-page screenshots and for background tabs; on Firefox without it the viewport falls back to captureVisibleTab ([browser-actions.ts#L124-L150](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/firefox/actions/browser-actions.ts#L124-L150)).
- browser.tabGroups (Firefox 139 and later) is used when present with a tracking fallback for older builds ([background.ts#L35-L65](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/firefox/background.ts#L35-L65)).
- sidebar_action with a toolbar toggle ([manifest.json#L26-L35](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/firefox/manifest.json#L26-L35), [background.ts#L753-L760](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/firefox/background.ts#L753-L760)) is a Firefox-specific UI; a stable-Firefox companion's sidebar would be built the same way.
- The Chrome-only DevTools protocol path (debugger permission, [manifest.json#L6-L14](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/manifest.json#L6-L14), [browser-actions.ts#L28-L58](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/actions/browser-actions.ts#L28-L58)) has no Firefox counterpart in this code. Firefox's own page-side screenshot and script paths are what replace it.
- Keyboard and click events are synthetic (dispatchEvent) in the Firefox build ([browser-actions.ts#L372-L389](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/firefox/actions/browser-actions.ts#L372-L389), [browser-actions.ts#L539-L566](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/src/firefox/actions/browser-actions.ts#L539-L566)); pages that check event.isTrusted will see them as untrusted, and default actions such as text insertion from a key are not performed.
- Unsigned temporary add-on loading is the documented install path ([README.md#L70-L74](https://github.com/smankoo/open-browser-control/blob/f82b6afad22b483950a6013de375422346828027/README.md#L70-L74)); a stable-Firefox release needs an AMO-signed build, which this repository does not produce.
