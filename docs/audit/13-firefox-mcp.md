- Summary: A Node.js MCP server (stdio transport, @modelcontextprotocol/sdk) that drives an existing or launched Firefox through selenium-webdriver, geckodriver, the Marionette remote agent and WebDriver BiDi. It registers 57 tools in 19 modules, grouped into presets slim, basic (default), developer, mozilla and all, and it ships no browser extension, sidebar or popup. Privileged modules (prefs, privileged) and moz-only modules (launch, bidi) are compiled out of the public entry point.

## Architecture

- Transport: MCP client to the Node process over stdio ([index.ts#L231-L242](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/index.ts#L231-L242) [index.ts#L310-L311](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/index.ts#L310-L311)); there is no HTTP or WebSocket listener in this server.
- Server language and SDK: TypeScript on Node.js, @modelcontextprotocol/sdk, yargs for flags ([cli.ts#L1-L10](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/cli.ts#L1-L10)), built with the npm scripts in [package.json#L2-L6](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/package.json#L2-L6).
- Firefox side, hop 1: selenium-webdriver starts geckodriver (launch or --connect-existing) with webSocketUrl enabled ([core.ts#L244-L300](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/firefox/core.ts#L244-L300) [core.ts#L336-L377](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/firefox/core.ts#L336-L377)); geckodriver talks to Firefox over the Marionette port on 127.0.0.1 ([core.ts#L140-L175](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/firefox/core.ts#L140-L175) [cli.ts#L111-L121](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/cli.ts#L111-L121)).
- Firefox side, hop 2: page-level commands use WebDriver BiDi through the session ([bidi.ts#L189-L195](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/firefox/bidi.ts#L189-L195) [bidi.ts#L226-L244](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/firefox/bidi.ts#L226-L244)); DOM snapshots and element resolution run an injected bundle in a named sandbox realm ([manager.ts#L44-L88](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/firefox/snapshot/manager.ts#L44-L88) [manager.ts#L194-L228](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/firefox/snapshot/manager.ts#L194-L228)).
- Browser side: none of its own. There is no WebExtension manifest or content script in the tracked tree; the only extension-like file is tests/fixtures/test-extension (listed in the tree, not read).
- Claude or LLM sidebar UI: none in the tree.
- Installer and platforms: npm package @mozilla/firefox-mcp with a bin entry ([package.json#L8-L13](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/package.json#L8-L13)), an MCPB bundle ([manifest.mcpb.json#L14-L30](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/manifest.mcpb.json#L14-L30)), Dockerfile ([Dockerfile#L1-L63](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/Dockerfile#L1-L63), see 13-F47) and plugin manifests (13-F45, 13-F46). The startup check requires Node.js 20 or later ([index.ts#L25-L30](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/index.ts#L25-L30)). Firefox binary detection and geckodriver lookup handle Windows paths separately ([windows-binary.ts](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/firefox/windows-binary.ts) [core.ts#L30-L41](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/firefox/core.ts#L30-L41) [core.ts#L67-L75](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/firefox/core.ts#L67-L75)).

## Permission boundaries

- Manifest permissions: none. The repository contains no WebExtension manifest that it installs or runs; install_extension can install other add-ons (see F24).
- Host permissions: none declared by this repository.
- Per-tab or per-site grant: none enforced. Every tab in the Firefox session is reachable through the tab tools ([pages.ts#L226-L255](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/firefox/pages.ts#L226-L255)), and evaluate_script, screenshots and input tools act on the selected tab without any user confirmation ([script.ts#L71-L184](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/tools/script.ts#L71-L184)).
- Authentication: no authentication between the MCP client and the server (stdio, [index.ts#L310-L311](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/index.ts#L310-L311)). Between the server and Firefox, geckodriver connects to Marionette on 127.0.0.1 with no token; the port defaults to 2828 ([cli.ts#L117-L121](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/cli.ts#L117-L121)) and the Marionette probe only checks reachability ([core.ts#L140-L175](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/firefox/core.ts#L140-L175)). No token storage exists. Bind address is whatever Firefox chose; this code does not set one.
- Sensitive-action gating: privileged modules are dropped unless the build allows them, and the default is to fail closed ([registry.ts#L59-L72](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/tools/registry.ts#L59-L72) [registry.ts#L32-L34](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/tools/registry.ts#L32-L34); public entry [index.public.ts#L16-L27](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/index.public.ts#L16-L27)). send_bidi_command refuses session.end, session.new and browser.close ([bidi.ts#L6-L7](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/tools/bidi.ts#L6-L7) [bidi.ts#L41-L77](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/tools/bidi.ts#L41-L77)). Dialogs block tool calls by default ([module.ts#L95-L120](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/tools/module.ts#L95-L120)). saveTo paths are restricted unless --unrestricted-save-paths ([save-output.ts#L73-L124](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/utils/save-output.ts#L73-L124) [cli.ts#L213-L218](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/cli.ts#L213-L218)). No redaction, confirmation prompt or audit record beyond the tool-name log ([index.ts#L263-L266](https://github.com/mozilla/firefox-mcp/blob/02c5df84e6ec492be07796479df3883ce462e33c/src/index.ts#L263-L266)).

## Firefox implementation notes

- A stable Firefox WebExtension can reach the bridge features that rely on normal extension APIs: tabs (browser.tabs), scripting and content scripts, screenshots (browser.tabs.captureTab), downloads (browser.downloads) and page-world script evaluation. These are 13-F01, 13-F02, 13-F03, 13-F04, 13-F19 and the non-trusted parts of 13-F05 to 13-F07.
- These need a remote agent that a stable WebExtension cannot use, and are therefore unavailable in a Firefox-native design: geckodriver and Marionette attachment and launch (13-F18, 13-F30), WebDriver BiDi commands with moz: prefixes or remote-agent-only methods (13-F09, 13-F12, 13-F14, 13-F15, 13-F20 to 13-F23, 13-F24, 13-F25, 13-F26, 13-F27), and the privileged chrome context (13-F25, 13-F26), which also needs MOZ_REMOTE_ALLOW_SYSTEM_ACCESS.
- Trusted input is the main gap. click_by_uid and type paths use WebDriver input.performActions (13-F05, 13-F07, 13-F06); a WebExtension can only dispatch synthetic events, which some pages ignore.
- File upload from a local path (13-F06) and add-on install from a path (13-F24) need remote-agent commands; an extension would need a user gesture or a file picker.
- Network bodies (13-F08) need the BiDi data collector; webRequest gives metadata only.
- Stable Firefox loads only signed add-ons; this repository has no add-on packaging, so an add-on build would need its own manifest, signing and permissions.
- Adapt, for rows not named above: the browser console (13-F10) is reachable through BiDi log events, while an extension would see only page console calls through a content script. Element and full-page screenshots (13-F11) need page-side cropping on top of browser.tabs.captureTab, which gives the visible viewport only. Download tracking and a folder (13-F13) fit browser.downloads, but the deny and default modes are a remote-agent setting. Closing the browser (13-F17) is a session-level command, while an extension can only disconnect its own socket. The stdio Node process (13-F29) would be replaced by native messaging or a socket transport.
- Unavailable, for rows not named above: get_firefox_output (13-F16) reads the output file of a Firefox process this server launched, and a WebExtension has no equivalent. The Node server packaging (13-F33) is not a Firefox add-on, so nothing in it is signed for the stable Firefox add-on channel.
