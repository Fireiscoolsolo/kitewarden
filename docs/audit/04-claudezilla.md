- Summary: A Claude Code MCP server (Node.js, stdio) plus a Node native messaging host and a Firefox MV2 WebExtension that together give Claude Code about 36 browser tools over a shared 12-tab pool in the user's real Firefox. The MCP server talks to the host over a local Unix socket or a Windows named pipe with a per-start random token, and the host relays JSON commands to the extension over native messaging. The extension drives tabs with the tabs, windows and webRequest APIs and does DOM work in a content script.

## Architecture

Hops from the MCP client to the page:

1. MCP client (Claude Code) to MCP server: stdio transport from the MCP SDK ([server.js#L10-L15](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/mcp/server.js#L10-L15), connected in [server.js#L2045-L2049](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/mcp/server.js#L2045-L2049)).
2. MCP server to native host: one JSON line per request over a local socket, with the auth token read from the token file on every command ([server.js#L571-L615](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/mcp/server.js#L571-L615), [socket-request.js#L31-L61](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/mcp/socket-request.js#L31-L61)). 3. ## Firefox implementation notes

- Already WebExtension APIs and Firefox-specific calls in use: browser.tabs.captureTab ([background.js#L1993-L1999](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/extension/background.js#L1993-L1999)), browser.tabGroups and browser.tabs.group, which the code comment says need Firefox 138 or later ([background.js#L1216-L1229](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/extension/background.js#L1216-L1229)), and browser.extension.isAllowedIncognitoAccess ([background.js#L831-L833](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/extension/background.js#L831-L833)). All are native on stable Firefox, but the group calls need a version check in the Companion.
- Private windows: the extension must be allowed to run in private windows by the user. The code reads that setting and falls back to a regular window ([background.js#L1199-L1212](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/extension/background.js#L1199-L1212)). A Companion aimed at the existing signed-in profile should not rely on private windows.
- Trusted input: clicks, key presses and typing are synthetic (isTrusted false) in every path ([pointer-click.js#L96-L183](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/extension/pointer-click.js#L96-L183), [content.js#L2099-L2132](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/extension/content.js#L2099-L2132)). Pages that check isTrusted cannot be driven this way on any Firefox; this is a WebExtension limit, not a Firefox version limit.
- Page-world execution: this repo runs evaluate in the content-script context, which cannot reach page globals, and it uses no page-world script. If a Companion needs page-world evaluation it needs its own injection path and must accept strict-CSP failures, as this code's comment already says ([content.js#L264-L268](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/extension/content.js#L264-L268)).
- MV2 persistent background: the extension uses a persistent background page and webRequest with blocking permissions ([manifest.json#L26-L31](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/extension/manifest.json#L26-L31)). Whether stable Firefox 160 still accepts MV2 manifests was not verified in this audit.
- Unsigned installation: the Linux installer's headless profile depends on signature enforcement being off ([install-linux.sh#L346-L348](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/install/install-linux.sh#L346-L348)), which stable Firefox does not allow. The Companion must ship an AMO-signed package and must not use this route.
- Native messaging on Windows: the installer uses an HKCU NativeMessagingHosts key plus a .bat wrapper ([install-windows.ps1#L108-L121](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/install/install-windows.ps1#L108-L121)). This is a standard path for stable Firefox, but the .bat wrapper and Node.js runtime path must be replaced or verified for the Companion.
- Stop hook and autostart: these are Claude Code plugin and operating-system features, not Firefox features, and do not transfer to a Firefox-native design unchanged.
- Screenshots: captureTab and captureVisibleTab are used, and the code selects or captures tabs in a way that avoids switching the user's visible tab where possible ([background.js#L1893-L1906](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/extension/background.js#L1893-L1906)). The Companion should keep that behaviour.
- Storage: pool state and attachments persist in storage.local ([background.js#L70-L84](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/extension/background.js#L70-L84), [background.js#L151-L157](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/extension/background.js#L151-L157)) and survive restarts with adoption and sweep logic ([background.js#L87-L144](https://github.com/boot-industries/claudezilla/blob/5e4a23795d5813224b6eda038cc035d7afc8e508/extension/background.js#L87-L144)). This is native and worth keeping as a design reference.
- Sidebar: this repo has no sidebar. Firefox's own sidebar_action is available to the Companion but is not used here.
