- Summary: ccfox is an MV2 WebExtension for Zen and Firefox that adds a side-panel chat and gives Claude Code MCP tools to drive the user's own browser profile. A Node native messaging host bridges the extension to a per-user Unix socket that the MCP stdio server uses, and it runs the user's local `claude` CLI through the Agent SDK for side-panel chats. Page input is simulated with DOM events from a content-script agent, with no CDP.

## Architecture

Hops from an MCP client to the page (Claude Code path):

1. Claude Code starts the stdio MCP server, which is the package main entry point and registers the browser tools under the server name ccfox ([mcp-server.mjs#L1-L8](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/server/mcp-server.mjs#L1-L8), [mcp-server.mjs#L102-L104](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/server/mcp-server.mjs#L102-L104), [package.json#L2-L4](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/package.json#L2-L4)).
2. The MCP server connects to the bridge socket at the CCFOX_HOME path, or ~/.ccfox/bridge.sock by default. It sends a hello that carries CCFOX_CHAT_ID when set, then writes one JSON request per line ([mcp-server.mjs#L10-L11](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/server/mcp-server.mjs#L10-L11), [mcp-server.mjs#L27-L35](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/server/mcp-server.mjs#L27-L35), [mcp-server.mjs#L81-L92](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/server/mcp-server.mjs#L81-L92)).
3. The native host listens on that socket, tags each request with a client id, and forwards it to the extension over native messaging stdio ([native-host.mjs#L159-L190](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/host/native-host.mjs#L159-L190), [native-host.mjs#L192-L209](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/host/native-host.mjs#L192-L209), [native-host.mjs#L86-L98](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/host/native-host.mjs#L86-L98)).
4. The extension connects with connectNative("ccfox") and dispatches each request to its TOOLS table ([background.js#L20-L29](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/background.js#L20-L29), [background.js#L78-L111](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/background.js#L78-L111)).
5. Page-facing tools call the in-page agent in the top frame with tabs.sendMessage, injecting it on demand. The manifest has no content_scripts entry, so every content script is injected with executeScript or contentScripts.register ([background.js#L196-L237](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/background.js#L196-L237), [agent.js#L10-L11](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/content/agent.js#L10-L11), [manifest.json#L22-L41](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/manifest.json#L22-L41)).

Side-panel path: the sidebar page (sidebar/panel.html) talks over a runtime port named "panel" to chat.js, which sends chat.* messages to the native host ([chat.js#L139-L148](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/chat.js#L139-L148), [chat.js#L286-L343](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/chat.js#L286-L343)). For each chat the host runs one long-lived Claude Agent SDK query that spawns the user's own `claude` binary. The host serves the browser tools in-process as an SDK MCP server named browser and calls back into the extension without the socket ([native-host.mjs#L398-L420](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/host/native-host.mjs#L398-L420), [native-host.mjs#L269-L276](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/host/native-host.mjs#L269-L276), [native-host.mjs#L233-L249](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/host/native-host.mjs#L233-L249)).

Server language and SDK: Node ESM (.mjs), @modelcontextprotocol/sdk ^1.32.2, zod ^4.6.7 and @anthropic-ai/claude-agent-sdk ^0.3.319 ([package.json#L18-L22](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/package.json#L18-L22)).

Browser side: WebExtension Manifest V2 with a persistent background page made of several scripts ([manifest.json#L2](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/manifest.json#L2), [manifest.json#L32-L41](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/manifest.json#L32-L41)). There is no CDP, Marionette or WebDriver BiDi in the product code. The agent states that it works without CDP and that its events are synthetic ([agent.js#L5-L9](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/content/agent.js#L5-L9)). It uses tabs.executeScript, contentScripts.register, webRequest, webNavigation, tabs.captureTab, and tabGroups where the API exists ([background.js#L305-L334](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/background.js#L305-L334), [background.js#L282-L302](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/background.js#L282-L302), [highlight.js#L82-L97](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/highlight.js#L82-L97)).

Claude or LLM sidebar UI: a sidebar_action panel at sidebar/panel.html, toggled by the toolbar button or the Alt+Shift+C command. The browser_action has no popup and there is no options page ([manifest.json#L42-L59](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/manifest.json#L42-L59), [background.js#L535-L537](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/background.js#L535-L537)). Panel features are in the feature rows below.

Installer and platforms: scripts/install.mjs supports macOS and Linux only and exits with an error on any other platform, including Windows ([install.mjs#L28-L31](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/scripts/install.mjs#L28-L31)). The README says Windows is not supported ([README.md#L24](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/README.md#L24)). No Windows code path exists anywhere in the repository; the only Windows-related text is that refusal and the README and store notes.

MCP surfaces: the stdio server and the in-process browser server both build their tools from one definitions list, so both expose the same 15 tools ([tools.mjs#L77-L90](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/server/tools.mjs#L77-L90)). No MCP resources or prompts are registered. The only server-side instructions are the INSTRUCTIONS string ([tools.mjs#L38-L45](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/server/tools.mjs#L38-L45)).

  - Claude Code MCP requests: none enforced. resolveTab accepts any tabId, or the active tab, and claim() only marks the tab as controlled for capture and highlighting ([background.js#L122-L144](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/background.js#L122-L144), [background.js#L152-L160](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/background.js#L152-L160)). Otherwise a permission card is shown ([chat.js#L8-L9](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/chat.js#L8-L9), [chat.js#L494-L511](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/chat.js#L494-L511)). - Authentication: between Claude Code and the native host the bridge socket has no token and no peer-credential check. ## Firefox implementation notes

- Windows install and native messaging (adapt): the installer refuses Windows ([install.mjs#L28-L31](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/scripts/install.mjs#L28-L31)). A stable-Firefox Windows install needs an HKCU native-messaging registry entry pointing at a manifest, and a .cmd or .exe launcher in place of the /bin/sh launcher ([install.mjs#L63-L71](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/scripts/install.mjs#L63-L71)). The claude lookup is POSIX-only ([native-host.mjs#L281-L298](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/host/native-host.mjs#L281-L298), [install.mjs#L83](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/scripts/install.mjs#L83)).
- Bridge socket (adapt): the host and MCP server use a Unix socket file and chmod 0600 with a 0700 folder ([native-host.mjs#L42-L43](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/host/native-host.mjs#L42-L43), [native-host.mjs#L215-L217](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/host/native-host.mjs#L215-L217)). Windows does not enforce these POSIX modes, so the transport would need a named pipe with a per-user ACL.
- Unsigned distribution (unavailable on stable Firefox): the install path depends on xpinstall.signatures.required being false ([install.mjs#L122-L128](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/scripts/install.mjs#L122-L128)), which the README says stable Firefox ignores ([README.md#L47](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/README.md#L47)). Stable Firefox therefore needs an AMO-signed build. The listing is still "coming soon" in the README ([README.md#L31](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/README.md#L31)).
- javascript_exec (unavailable): developer build only; the signed store build excludes it ([js-exec.js#L3-L7](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/js-exec.js#L3-L7), [sign-amo.mjs#L10-L13](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/scripts/sign-amo.mjs#L10-L13)).
- Signing and listing (adapt): the Keychain credential source is macOS-only ([sign-amo.mjs#L186](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/scripts/sign-amo.mjs#L186), [amo-listing.mjs#L36](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/scripts/amo-listing.mjs#L36)).
- Panel copy (adapt): "Mac" and "Zen" wording ([panel.js#L481](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/sidebar/panel.js#L481), [panel.js#L537](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/sidebar/panel.js#L537), [chat.js#L588](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/chat.js#L588)) is platform-specific text to replace on Windows and stable Firefox.
- Browser APIs that work on stable Firefox (native): tabs.captureTab, tabs.executeScript with files, contentScripts.register, webRequest without blocking, webNavigation, sidebarAction, browserAction badges, and tabGroups (the code checks typeof browser.tabs.group and strict_min_version is 140). The closed shadow root reads (openOrClosedShadowRoot) and exportFunction with wrappedJSObject are Firefox-specific and work in the same way on stable Firefox.
- Input (native, same limits): input is synthetic with isTrusted false, and stable Firefox WebExtensions have no trusted-input API either, so the limits stated in agent.js ([agent.js#L5-L9](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/content/agent.js#L5-L9)) apply unchanged.
- Test harness (adapt): the tests launch /Applications/Zen.app with a remote debugging port ([record-e2e.mjs#L76-L79](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/test/record-e2e.mjs#L76-L79), [e2e.mjs#L19](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/test/e2e.mjs#L19)). Running them on stable Firefox or Windows needs a different launch and port setup.
- Manifest V2: the package targets MV2 with a persistent background page ([manifest.json#L32-L41](https://github.com/thedankest/ccfox/blob/b83591afc331fabcdae5918016c0fd20f9016151/extension/manifest.json#L32-L41)). Whether Firefox 160 supports this manifest version for the webRequest and persistent background used here was not checked in the repository.
