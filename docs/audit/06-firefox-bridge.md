- Summary: A Firefox WebExtension (Manifest V2, strict_min_version 153.0) plus a Node.js native-messaging host and an MCP stdio server. MCP clients such as Claude Code call 46 tools on the firefox-bridge server, and a separate firefox-bridge-bot server adds 3 script tools, to read or act on the user's already-open Firefox tabs through browser.tabs, scripting and content scripts, without CDP or OS input simulation. Every call goes over a token-authenticated local socket to the native host and then over native messaging to the extension, which enforces per-tab leases and a URL blacklist. The Node packages have unit and integration tests; the extension itself has no automated tests.

## Architecture

- Server language and SDK: JavaScript ES modules on Node 20 or later ([package.json#L11-L13](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/package.json#L11-L13) declares engines in the root package; the MCP server is [index.js#L2-L3](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/mcp-server/src/index.js#L2-L3) using @modelcontextprotocol/sdk McpServer and StdioServerTransport, with zod schemas in [tools.js#L2](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/mcp-server/src/tools.js#L2)). The server is created with name firefox-bridge and version 0.1.0 and no server instructions ([index.js#L12-L13](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/mcp-server/src/index.js#L12-L13)). Tools are registered in one function ([tools.js#L22-L23](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/mcp-server/src/tools.js#L22-L23)); no prompts, resources or skills are registered anywhere in the repository.
- Hop 1, MCP client to mcp-server: stdio, started by the MCP client ([index.js#L15-L16](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/mcp-server/src/index.js#L15-L16)). No authentication on this hop.
- Hop 2, mcp-server to native host: a local control socket. On Unix it is bridge.sock inside the bridge directory; on Windows it is a named pipe whose name is a 16-hex-digit SHA-256 prefix of the lower-cased directory path ([bridge-dir.js#L8-L13](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/bridge-dir.js#L8-L13) and [bridge-dir.js#L18-L22](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/bridge-dir.js#L18-L22)). The bridge directory is XDG_RUNTIME_DIR/firefox-bridge when that variable is set, otherwise the home directory's .firefox-bridge folder ([bridge-dir.js#L8-L13](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/bridge-dir.js#L8-L13)). The host writes a fresh 32-byte random hex token to the file named token in that directory and requires it as the first frame ([socket-server.js#L22-L37](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/socket-server.js#L22-L37) and [socket-server.js#L59-L69](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/socket-server.js#L59-L69)). The client reads that file ([bridge-client.js#L61-L65](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/mcp-server/src/bridge-client.js#L61-L65)).
- Hop 3, native host to Firefox: Native Messaging over stdio. The extension opens the port with connectNative for host name firefox_bridge_native_host ([background.js#L52-L54](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L52-L54)). Frames are a 4-byte little-endian length plus JSON, capped at 1 MiB on this hop ([native-messaging.js#L3](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/native-messaging.js#L3) and [native-messaging.js#L22-L41](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/native-messaging.js#L22-L41)). The host process is launched only for the extension ID listed in the installed manifest ([install-native-manifest.js#L123-L129](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/scripts/install-native-manifest.js#L123-L129)).
- Hop 4, extension to pages: content-script.js runs in every frame at document_idle in the isolated world ([manifest.json#L37-L43](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/manifest.json#L37-L43)); webmcp-relay.js runs at document_start in the top frame only ([manifest.json#L44-L48](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/manifest.json#L44-L48)). Two page-world scripts are registered per whitelisted hostname with browser.contentScripts.register and world MAIN, the dialog hook and the WebMCP shim ([background.js#L196-L208](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L196-L208) and [background.js#L297-L308](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L297-L308)). console-inject.js is run in the MAIN world with scripting.executeScript only when start_console is called, so it covers the top frame only ([background.js#L2434-L2438](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L2434-L2438)).
- Hop 5, dialog path: the dialog hook makes a synchronous XHR POST to http://127.0.0.1 on an OS-assigned port with an X-Dialog-Token header ([dialog-hook.js#L35-L62](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/dialog-hook.js#L35-L62)). The native host's DialogServer listens on 127.0.0.1 ([dialog-server.js#L50-L61](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/dialog-server.js#L50-L61)) and checks the token ([dialog-server.js#L125-L129](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/dialog-server.js#L125-L129)). Dialog requests never reach Firefox: list_dialogs and respond_dialog are answered inside the host ([index.js#L213-L221](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/index.js#L213-L221)).
- Lease state: the enforced tab-lease table is in the extension (leaseOwner map, [background.js#L46-L48](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L46-L48)). The native host also has a SessionManager lease table ([session-manager.js#L22-L32](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/session-manager.js#L22-L32)), but no code outside its tests calls its lease methods, so it is not on the enforcement path.
- Browser side: WebExtension Manifest V2 with a persistent background page whose scripts are listed in the manifest ([manifest.json#L2](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/manifest.json#L2) and [manifest.json#L33-L36](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/manifest.json#L33-L36)). The code uses tabs, windows, scripting, webNavigation, webRequest, menus, bookmarks, history, contextualIdentities, storage and extension.isAllowedIncognitoAccess. No WebDriver BiDi, Marionette, CDP or chrome.debugger use exists; the word debugger appears only inside a tool description ([tools.js#L39-L39](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/mcp-server/src/tools.js#L39-L39)).
- Sidebar or chat UI: none. The browser action has no popup ([manifest.json#L32-L32](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/manifest.json#L32-L32)). The only extension pages are the options page ([manifest.json#L50-L52](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/manifest.json#L50-L52)) and the blacklist confirmation window ([background.js#L701-L712](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L701-L712)). The toolbar button and the Firefox Bridge tab menu are used only for pending tab-selection requests ([background.js#L809-L828](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L809-L828)).
- Installer and packaging: scripts/install-native-manifest.js writes the native manifest and a launcher for Windows, macOS and Linux, with a LibreWolf option ([install-native-manifest.js#L22-L34](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/scripts/install-native-manifest.js#L22-L34) and [install-native-manifest.js#L36-L59](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/scripts/install-native-manifest.js#L36-L59)). scripts/sign-extension.js runs web-ext lint and then web-ext sign for the unlisted channel ([sign-extension.js#L73-L82](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/scripts/sign-extension.js#L73-L82)). The supported platforms are the ones these branches name: win32, darwin and linux ([install-native-manifest.js#L42-L58](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/scripts/install-native-manifest.js#L42-L58)).
- Second MCP server: firefox-bridge-bot is a separate process with its own registration ([index.js#L46-L53](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/firefox-bridge-bot/index.js#L46-L53)). It connects to the same socket with the same token, one connection per tool call ([bridge.js#L25-L30](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/firefox-bridge-bot/lib/bridge.js#L25-L30)), and registers one MCP tool per file in its scripts folder ([index.js#L23-L44](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/firefox-bridge-bot/index.js#L23-L44)).
- Size and time limits: native-messaging frames are capped at 1 MiB ([native-messaging.js#L3](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/native-messaging.js#L3)); the socket cap is 64 MiB ([native-messaging.js#L9](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/native-messaging.js#L9)); screenshots are sent in 700 KiB chunks ([background.js#L37-L37](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L37-L37)). Timeouts: user confirmation 60 s ([background.js#L12-L15](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L12-L15)), native host request 90 s ([index.js#L24-L24](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/index.js#L24-L24)), mcp-server request 100 s ([bridge-client.js#L29-L30](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/mcp-server/src/bridge-client.js#L29-L30)), dialog answer 30 s ([dialog-server.js#L25-L25](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/dialog-server.js#L25-L25)), WebMCP tool call 20 s ([background.js#L458-L458](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L458-L458)), tab-selection request 120 s ([background.js#L790-L790](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L790-L790)).

## Permission boundaries

- Manifest permissions: nativeMessaging, tabs, activeTab, webNavigation, webRequest, history, bookmarks, storage, scripting, contextualIdentities, cookies, menus, clipboardRead, clipboardWrite, and <all_urls> ([manifest.json#L15-L31](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/manifest.json#L15-L31)). Two of these have no API call in the repository: activeTab and cookies (searched for browser.cookies, cookies. and activeTab in every JavaScript file, nothing found).
- Host permissions: there is no host_permissions key. Host access comes from the <all_urls> entry in permissions ([manifest.json#L30-L30](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/manifest.json#L30-L30)) and from the content_scripts matches for <all_urls> ([manifest.json#L38-L49](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/manifest.json#L38-L49)). At runtime the extension adds per-hostname content scripts for the patterns *://host/* and *://*.host/* ([background.js#L198-L201](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L198-L201) and [background.js#L297-L300](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L297-L300)). Network observation uses <all_urls> ([background.js#L2476-L2477](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L2476-L2477)).
- Per-tab or per-site grant: Per tab, a session gets a lease by calling acquire_tab (with a tabId) or open_private_window, and the lease is recorded in the extension's leaseOwner map ([background.js#L1203-L1317](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L1203-L1317)). No user prompt is involved in leasing an existing tab; acquire_tab with a tabId checks only the blacklist on the tab's current URL ([background.js#L1213-L1221](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L1213-L1221)). A tab leased by another session returns conflict ([background.js#L724-L729](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L724-L729)). Per site, the only grant mechanism is the blacklist: a URL or hostname the user lists in options triggers a popup with Allow once, Allow for this session, or Deny ([background.js#L649-L697](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L649-L697) and [confirm.js#L1-L16](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/popup-confirm/confirm.js#L1-L16)). Once grants are kept per exact URL and session grants per hostname and session ([policy-gate.js#L26-L33](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/policy-gate.js#L26-L33) and [background.js#L658-L669](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L658-L669)). The blacklist starts empty ([background.js#L12-L15](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L12-L15) and [background.js#L128-L131](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L128-L131)), so in a default install no site is gated at all. There is no allowlist: nothing requires the user to grant a tab or site before the MCP client can read or act on it.
- Authentication:
  - MCP client to mcp-server: none; the client launches the process over stdio ([index.js#L15-L16](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/mcp-server/src/index.js#L15-L16)).
  - mcp-server to native host: the first frame must be an auth message carrying the host token; a wrong token gets the socket destroyed with no reply ([socket-server.js#L59-L69](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/socket-server.js#L59-L69)). The comparison is plain string equality. The socket directory is created with mode 0700 and the token file with 0600 ([socket-server.js#L22-L27](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/socket-server.js#L22-L27)), but on Windows the code sets no explicit ACL on the named pipe or the token file. Each authenticated connection gets a new session id, and the host overwrites any client-supplied sessionId ([index.js#L225-L229](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/index.js#L225-L229)).
  - Native host to Firefox: no token. Firefox starts the host only for firefox-bridge@firefox-bridge.local ([install-native-manifest.js#L127-L128](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/scripts/install-native-manifest.js#L127-L128)).
  - Page-world dialog hook to native host: HTTP on 127.0.0.1 with an OS-assigned port ([dialog-server.js#L55-L59](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/dialog-server.js#L55-L59)) and a per-run X-Dialog-Token ([dialog-server.js#L125-L129](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/dialog-server.js#L125-L129)). The port and token are written into the page-world source ([dialog-hook.js#L29-L30](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/dialog-hook.js#L29-L30)), so any script running in a whitelisted page can read and reuse them. Every response carries Access-Control-Allow-Origin set to *, and no Origin check is made ([dialog-server.js#L110-L113](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/native-host/src/dialog-server.js#L110-L113)).
  - WebMCP: the relay forwards tool registrations from any page, and the background accepts one only when the sender URL's hostname is whitelisted and the frame is the top frame ([background.js#L395-L410](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L395-L410)). ## Firefox implementation notes

- Overall: the repository uses only WebExtension APIs. It has no CDP, Marionette or WebDriver BiDi code, and no OS input simulation. It is a Manifest V2 extension with a persistent background page ([manifest.json#L2-L2](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/manifest.json#L2-L2) and [manifest.json#L33-L36](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/manifest.json#L33-L36)). Whether the target build accepts Manifest V2 was not checked. A Manifest V3 port would replace the persistent background page and the MV2-only tabs.executeScript calls ([background.js#L2031-L2031](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L2031-L2031) and [background.js#L2265-L2265](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L2265-L2265)).
- Features that need a different implementation on stable Firefox, and why:
  - Private windows (06-F08, 06-F45, 06-F46, 06-F47): Firefox gives an extension no API to turn on "Run in Private Windows", so the user has to enable it in about:addons. The code preflights this ([background.js#L1328-L1329](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L1328-L1329)), and Kitewarden would need onboarding for it.
  - Page-world hooks (dialog hook, WebMCP shim, console capture; 06-F37, 06-F41, 06-F42): these need MAIN-world script injection through browser.contentScripts.register and scripting.executeScript ([background.js#L198-L208](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L198-L208) and [background.js#L2434-L2438](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L2434-L2438)). The repository's minimum is 153, so this should be checked on 160.
  - Dialog interception (06-F39, 06-F40, 06-F41): relies on a synchronous XHR from page context to 127.0.0.1 with CORS, which is a deprecated mechanism, and on CSP not blocking it. Kitewarden could use another channel, but that changes the blocking behaviour of alert, confirm and prompt.
  - Clipboard paste mode (06-F27): needs clipboardRead, clipboardWrite and execCommand paste in a content script, and it overwrites the user's OS clipboard as a side effect ([tools.js#L75-L75](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/mcp-server/src/tools.js#L75-L75)).
  - Windows native messaging (06-F54, 06-F55): the host is started through a .cmd launcher named in the native manifest. If Firefox 160 does not start it that way, the packaging must change.
  - Containers (06-F07, 06-F17): contextualIdentities is needed, and the code relies on the API error path when container tabs are unavailable ([background.js#L1256-L1262](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L1256-L1262)).
  - Permanent install (06-F56): an add-on needs a signed package for a stable Firefox install; this repository signs through AMO on the unlisted channel.
  - Screenshots above the single-capture ceiling (06-F36): Firefox fails captures over 32767 px per side, and the code cites the Mozilla bug for this ([background.js#L39-L44](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/extension/background.js#L39-L44)).
  - WebMCP shim (06-F42, 06-F43, 06-F44): the shim supplies document.modelContext itself, and the README says it would overwrite a native implementation if Firefox ever shipped one ([README.md#L365-L367](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/README.md#L365-L367)). Kitewarden on stable Firefox should first check whether a native API exists.
  - Tab-selection UI (06-F15, 06-F16): built from menus and a toolbar badge, with no popup, so a request can only be answered by right-clicking a tab ([README.md#L67-L69](https://github.com/raychao-oao/firefox-bridge/blob/e7bfb049801075500e5ddd7fb5cdbfe689f1feff/README.md#L67-L69)).
- Features that map directly to stable WebExtension APIs, with no change needed: tab and window control, scripting, navigation, webRequest observation, bookmarks, history, containers, menus and storage (every row marked native above).
