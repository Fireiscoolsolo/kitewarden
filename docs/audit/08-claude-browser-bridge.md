- Summary: A Manifest V2 Firefox extension plus a stdlib-only Python MCP server (server/bridge.py) that lets local Claude Code sessions drive the user's logged-in Firefox over a loopback-only HTTP long-poll ([bridge.py#L1-L18](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/server/bridge.py#L1-L18)). It registers 21 MCP tools; the browser side runs each one through an on-demand page agent or the background page. Safety controls are pause, read-only mode, host allowlist and blocklist, per-session disconnect and kill, and a popup-only evaluate toggle that is off by default.

## Architecture

- Hop 1, MCP client to server: newline-delimited JSON-RPC over stdio, read in a loop in main ([bridge.py#L448-L468](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/server/bridge.py#L448-L468)). Each Claude Code session starts its own bridge process ([README.md#L25](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/README.md#L25)). Supported protocol versions are 2025-06-18, 2025-03-26 and 2024-11-05 ([bridge.py#L46](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/server/bridge.py#L46)). The initialize reply advertises only the tools capability ([bridge.py#L427-L436](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/server/bridge.py#L427-L436)).
- Hop 2, server to extension: a ThreadingHTTPServer bound to 127.0.0.1 on the first free port in 8777-8786 ([bridge.py#L37](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/server/bridge.py#L37), [bridge.py#L267-L276](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/server/bridge.py#L267-L276)). The extension polls all ten ports ([background.js#L5](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/background.js#L5), [background.js#L80-L110](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/background.js#L80-L110)). GET /poll is held open up to 20 seconds ([bridge.py#L42](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/server/bridge.py#L42), [bridge.py#L137-L145](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/server/bridge.py#L137-L145)). Results come back by POST /result ([bridge.py#L231-L232](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/server/bridge.py#L231-L232), [background.js#L144-L151](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/background.js#L144-L151)).
- Hop 3, extension to page: the background page injects agent.js into the target frame's isolated world with scripting.executeScript files, then calls window.__cbbAgent ([background.js#L251-L266](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/background.js#L251-L266), [agent.js#L427-L435](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/agent.js#L427-L435)). Evaluate and the log helpers run in the page's MAIN world through a func argument ([background.js#L268-L275](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/background.js#L268-L275)).
- Native pairing: Firefox starts the native host launcher, which runs native/host.py ([host.py#L66-L80](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/native/host.py#L66-L80)). The host is registered only for the extension ID ([install.py#L49](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/native/install.py#L49)).
- Browser API: MV2 with a persistent background page and scripts guards.js then background.js ([manifest.json#L2](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/manifest.json#L2), [manifest.json#L7-L10](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/manifest.json#L7-L10)). All browser calls use the browser namespace. The extension code uses no WebDriver BiDi, Marionette or CDP. Marionette appears only in the test harness, which drives the popup through it ([e2e.py#L90-L92](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/test/e2e.py#L90-L92)).
- Sidebar, chat and in-page indicators: none. The only UI is a toolbar popup ([manifest.json#L11-L15](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/manifest.json#L11-L15), [popup.html#L26-L58](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/popup.html#L26-L58)) and a badge ([background.js#L64-L76](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/background.js#L64-L76)).
- Installer and packaging: native/install.py writes the launcher and host manifest under the user's .claude-browser-bridge folder and, on Windows, an HKCU key ([install.py#L23-L57](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/native/install.py#L23-L57)). scripts/sign.py signs an unlisted add-on with web-ext, or submits to the listing with --listed ([sign.py#L59-L86](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/scripts/sign.py#L59-L86)). Windows is the first branch; macOS and Linux branches also exist ([install.py#L24-L42](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/native/install.py#L24-L42)). Firefox 142 is the manifest minimum ([manifest.json#L21](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/manifest.json#L21)). ## Permission boundaries

- Manifest permissions: tabs, scripting, storage, nativeMessaging, webNavigation, <all_urls> ([manifest.json#L6](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/manifest.json#L6)). - Authentication: client to server is stdio, which has no auth of its own. The token is created at first run with 32 or more bytes and written with mode 600 where the OS allows ([bridge.py#L55-L67](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/server/bridge.py#L55-L67)). ## Firefox implementation notes

- Native messaging (pairing host and per-user HKCU registration on Windows) is a standard stable-Firefox mechanism and is used as-is. The allowed_extensions restriction is the trust boundary for the token ([install.py#L49](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/native/install.py#L49), [install.py#L53-L55](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/native/install.py#L53-L55)).
- The loopback HTTP long-poll bridge, the Python MCP server and the Kill/PID handshake are not browser features. A Kitewarden can keep them, or replace them with native messaging, but then the MCP server, the token handling and the audit log must be built by Kitewarden.
- MV2 with a persistent background page ([manifest.json#L7-L10](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/manifest.json#L7-L10)). Whether stable Firefox 160 accepts this manifest version was not verified in this audit; Kitewarden needs to check it before relying on the background-page design.
- scripting.executeScript with world MAIN (evaluate and log capture, [background.js#L268-L275](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/background.js#L268-L275)) and the injected isolated-world agent ([background.js#L251-L266](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/background.js#L251-L266)) use standard WebExtension APIs. CSP still applies to evaluate, as the README states ([README.md#L104](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/README.md#L104)).
- openOrClosedShadowRoot ([agent.js#L17](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/agent.js#L17)) is a Firefox-only extension capability. Kitewarden on Firefox can use it, but code that must also run on Chrome cannot.
- captureVisibleTab only captures the visible tab, so the screenshot tool activates the target tab first ([background.js#L427-L428](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/extension/background.js#L427-L428)). Kitewarden with a no-focus-steal rule needs a different capture route or must accept the focus change.
- Unsigned add-ons are blocked on release Firefox; the project signs unlisted through AMO and web-ext ([sign.py#L59-L62](https://github.com/jhueby/claude-browser-bridge/blob/58749d978a26d7b675225d15d6b17591034ab936/scripts/sign.py#L59-L62)). Kitewarden needs its own signing path.
- No Chrome-only API was seen in the files read. All calls go through the browser namespace.
