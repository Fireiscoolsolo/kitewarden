- Summary: Foxhand is a Firefox MV2 WebExtension plus a native messaging helper (Node code compiled with bun) that serves MCP over local HTTP with a bearer token. The helper exposes 45 MCP tools that the add-on runs in the user's existing profile: tab and window control, accessibility snapshots, clicks and form input through a content script, storage, bookmarks, history, downloads, cookies and recently closed sessions. There is no sidebar or chat UI; access is gated only by the token, a per-command confirm flag for four destructive tools, and a pause switch, and there is no per-site or per-tab grant.

## Architecture

Hops, from the MCP client to the page:

1. MCP client to helper, HTTP: stateless Streamable HTTP POST on /mcp, one McpServer per request ([http.ts#L442-L462](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/mcp-server/src/http.ts#L442-L462)). Default listen 127.0.0.1:8901 ([config.ts#L6](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/mcp-server/src/config.ts#L6), [config.ts#L17-L18](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/mcp-server/src/config.ts#L17-L18)); an IPv6 ::1 twin is added for loopback binds ([http.ts#L246-L253](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/mcp-server/src/http.ts#L246-L253)).
2. Alternative hop, stdio: `foxhand-helper mcp` runs a stdio MCP shim that forwards each tools/call to the localhost HTTP endpoint with a bearer token from the FOXHAND_TOKEN environment variable ([stdio.ts#L11-L19](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/mcp-server/src/stdio.ts#L11-L19), [stdio.ts#L24-L67](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/mcp-server/src/stdio.ts#L24-L67), [host.ts#L638-L640](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/mcp-server/src/host.ts#L638-L640)).
3. Helper to add-on, native messaging: Firefox starts the helper through runtime.connectNative ([background.ts#L1860-L1870](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/extension/src/background.ts#L1860-L1870)). Frames are 4-byte little-endian length plus UTF-8 JSON on stdin/stdout ([host.ts#L196-L234](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/mcp-server/src/host.ts#L196-L234)). The bridge matches responses by command id and enforces a 30 s default timeout ([bridge.ts#L88-L91](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/mcp-server/src/bridge/bridge.ts#L88-L91), [bridge.ts#L242-L246](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/mcp-server/src/bridge/bridge.ts#L242-L246)).
4. Add-on background: MV2 persistent background page ([manifest.json#L42-L49](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/extension/manifest.json#L42-L49)) with a handler table keyed by bridge method ([background.ts#L1107-L1108](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/extension/src/background.ts#L1107-L1108)).
5. Background to page: the manifest injects content/cursor.js and content/ax.js into the top frame of every page at document_idle ([manifest.json#L50-L62](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/extension/manifest.json#L50-L62)); the add-on re-injects them on demand, and injects ax.js alone into a cross-origin frame that a call addresses ([background.ts#L250-L267](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/extension/src/background.ts#L250-L267)). - Per-tab or per-site grant: none enforced. resolveTab returns any tab by id, or the active tab ([background.ts#L219-L233](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/extension/src/background.ts#L219-L233)). - Authentication: harness to helper requires `Authorization: Bearer <token>` on POST, GET and DELETE /mcp ([http.ts#L379-L387](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/mcp-server/src/http.ts#L379-L387), [http.ts#L462](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/mcp-server/src/http.ts#L462), [http.ts#L470-L471](https://github.com/hamb1y/foxhand/blob/ad4a35df50666cd9849daf199441fce467519889/mcp-server/src/http.ts#L470-L471)). ## Firefox implementation notes

- Native messaging host (runtime.connectNative, native manifest with allowed_extensions, HKCU key on Windows) works on stable Firefox without signing the helper. The helper is a separate binary the user installs; a Kitewarden that wants an MCP bridge without a native helper would need a different transport.
- Manifest version 2 with persistent background scripts (manifest.json line 2 and lines 42-49). A new stable-Firefox 160 build should decide MV2 or MV3 on its own terms; this audit does not assess that.
- Firefox-specific APIs in use: tabs.captureTab with a captureVisibleTab fallback (background.ts 699-704), tabs.updateMutedInfo (background.ts 1268-1271), cookies with firstPartyDomain, partitionKey and storeId (background.ts 985-1019, 1568-1595), downloads, sessions and bookmarks. Each is a standard WebExtension API on stable Firefox, but the cookie partition handling is Firefox-specific and must be reproduced.
- Content script shadow access uses openOrClosedShadowRoot (ax.ts 84-87), a Firefox-only accessor for closed shadow roots; Chrome-only builds would need a different approach.
- Dialog interception replaces page window alert, confirm and prompt through wrappedJSObject and exportFunction (ax.ts 3212-3240). This is Firefox's Xray mechanism and it is the main page-world write in the add-on. It runs from the isolated-world content script and needs a Firefox-specific implementation if reused.
- Data-collection consent uses browser_specific_settings.gecko.data_collection_permissions (manifest.json 18-28) and permissions.request/remove (options.ts 367-396). This is a Firefox mechanism that the stable release honors.
- Packaging: the add-on is signed via AMO with web-ext (amo-sign.sh 84-101); the helper ships outside Firefox with SHA256SUMS and, on macOS, ad-hoc signing (install.sh 44-79).
- Features with no alternative needed: the MCP server, helper, installers and token auth are not browser-specific and run unchanged outside the add-on.
