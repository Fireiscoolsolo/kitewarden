- Summary: Claude in Chrome is Anthropic's browser extension that lets Claude read and act on pages in the user's signed-in Chromium browser, and Claude Code reaches it through 20 MCP tools. This audit covers the product page, the Claude Code Chrome docs and the recorded tool schemas only; no source code was in scope. Statements with no detail behind them are marked claimed-only.

## Architecture

- Client to browser: Claude Code starts the connection with `claude --chrome` or the `/chrome` setting, and the browser actions are exposed as MCP tools named `mcp__claude-in-chrome__*` ([schema 2026-11-23](https://code.claude.com/docs/en/chrome)); see [Get started in the CLI](https://code.claude.com/docs/en/chrome#get-started-in-the-cli).
- Native messaging host: on first enable Claude Code installs a native messaging host configuration file, which Chrome reads on startup; per-browser file paths on macOS and Linux and Windows registry keys are listed in [Extension not detected](https://code.claude.com/docs/en/chrome#extension-not-detected).
- Bridge: the extension must reach `bridge.claudeusercontent.com`, and Windows uses a named pipe that the docs say can conflict (EADDRINUSE); see [Common error messages](https://code.claude.com/docs/en/chrome#common-error-messages) and [Windows-specific issues](https://code.claude.com/docs/en/chrome#windows-specific-issues).
- Browser side: a Chrome extension whose service worker can go idle and break the connection ([Connection drops during long sessions](https://code.claude.com/docs/en/chrome#connection-drops-during-long-sessions)).
- Side panel UI: the product page describes a Chrome side panel as one of three access points, alongside Claude and Claude Code ([product page](https://claude.com/claude-in-chrome)).
- Installer and platforms: installed from the Chrome Web Store at version 1.0.36 or later ([Prerequisites](https://code.claude.com/docs/en/chrome#prerequisites)); Google Chrome and Microsoft Edge are supported, Brave, Arc, Vivaldi and Opera are detected, and WSL is not supported ([docs intro](https://code.claude.com/docs/en/chrome)).
- Not stated in the sources: WebExtension manifest version, the message transport between the native host and the extension, and any use of WebDriver, Marionette or CDP.

## Permission boundaries

- Manifest permissions: not stated in the sources.
- Host permissions: not stated in the sources.
- Per-tab or per-site grant: the user approves a site when Claude Code asks, and can allow all actions on that site for the session ([Manage site permissions](https://code.claude.com/docs/en/chrome#manage-site-permissions)); the tools act only on tabs in the session's MCP tab group ([schema 2026-11-23](https://code.claude.com/docs/en/chrome)). No code was reviewed, so enforcement is as described by the sources only.
- Authentication: `/login` is required, and an API key or long-lived token keeps Chrome integration off ([Prerequisites](https://code.claude.com/docs/en/chrome#prerequisites)); the extension must be signed in to the same claude.ai organization as Claude Code ([Extension signed in to a different organization](https://code.claude.com/docs/en/chrome#extension-signed-in-to-a-different-organization)). Token storage, origin checks and bind address: not stated in the sources.
- Sensitive-action gating: the product page says purchases, financial actions and anything irreversible wait for the user, without listing them ([product page](https://claude.com/claude-in-chrome)); plan mode prompts before a GIF recording or a new tab ([Browser tools in plan mode](https://code.claude.com/docs/en/chrome#browser-tools-in-plan-mode)); `action_summary` describes each mutating action to the user and `read_network_requests` shows auth values as REDACTED ([schema 2026-11-23](https://code.claude.com/docs/en/chrome)); file upload refuses files the session may not read, credential-named files and hard-linked files ([Upload files to web pages](https://code.claude.com/docs/en/chrome#upload-files-to-web-pages)).
- Gaps: the product page says Claude "asks before sensitive actions" but does not define which actions count ([product page](https://claude.com/claude-in-chrome)). The docs say that in auto mode the extension can skip its own per-site check for a call the classifier approves, unless permission rules deny a site ([Manage site permissions](https://code.claude.com/docs/en/chrome#manage-site-permissions)); this is a risky default for any site not covered by a deny rule.

## Firefox implementation notes

- Native messaging host: the docs name per-browser config paths and Windows registry keys for Chrome, Edge and other Chromium browsers; a stable Firefox 160 build needs its own host registration, which the sources do not describe ([docs](https://code.claude.com/docs/en/chrome#extension-not-detected)).
- Install and browser-specific names: the docs install through the Chrome Web Store and point to `chrome://extensions`; a Firefox build would need its own signed add-on install path, not verified here ([docs](https://code.claude.com/docs/en/chrome#extension-not-detected)).
- Side panel and tab groups: the Chrome side panel and Chrome tab groups (24-F13, 24-F15, 24-F29) need Firefox equivalents for the sidebar and grouping; the sources state no mapping.
- Standard WebExtension-style tab and window tools (24-F30, 24-F31, 24-F32, 24-F44) and text extraction (24-F37) are the closest fit to a stable Firefox WebExtension.
- Page-level tools (computer, read_page, find, form_input, javascript_tool, read_console_messages, read_network_requests, file_upload, upload_image, gif_creator) use mechanisms the schemas do not name, so each needs a Firefox implementation check; auth redaction in read_network_requests must be rebuilt.
- Service worker: the docs tie reconnect behavior to a Chrome service worker going idle (24-F08); a Firefox background context would have a different lifecycle, not verified here.
- Multi-browser pairing (24-F07, 24-F46 to 24-F48) depends on the account bridge, which the docs tie to Chromium browsers.
