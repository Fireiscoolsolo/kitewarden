- Summary: A Python MCP server (FastMCP, published as firefox-browser-mcp) exposes 27 browser tools and hosts a local WebSocket bridge on 127.0.0.1:9010 by default. A Firefox MV2 companion extension connects to that bridge as a client and runs each command against any tab it can reach, doing DOM work in a content script and network capture with webRequest. The code has no authentication on the bridge, no origin check, and no per-tab or per-site permission model.

## Firefox implementation notes

- filterResponseData (used for XHR response bodies, [background.js#L276-L310](https://github.com/ICWR-TEAM/Firefox-Browser-MCP/blob/2d475661406eb06788fcc505c39b72e1882c3b90/firefox-extension/background.js#L276-L310)) is Firefox-only and needs webRequestBlocking, which is declared ([manifest.json#L19-L20](https://github.com/ICWR-TEAM/Firefox-Browser-MCP/blob/2d475661406eb06788fcc505c39b72e1882c3b90/firefox-extension/manifest.json#L19-L20)). The Companion can keep this on Firefox, but the manifest version it needs must still be accepted by stable Firefox 160; that was not verified here.
- The manifest is MV2 with a persistent background ([manifest.json#L24-L26](https://github.com/ICWR-TEAM/Firefox-Browser-MCP/blob/2d475661406eb06788fcc505c39b72e1882c3b90/firefox-extension/manifest.json#L24-L26)). Stable Firefox 160's MV2 support was not verified in this audit.
- Console hook: injected.js is loaded as a page script from a web-accessible resource ([content.js#L36-L43](https://github.com/ICWR-TEAM/Firefox-Browser-MCP/blob/2d475661406eb06788fcc505c39b72e1882c3b90/firefox-extension/content.js#L36-L43)). The eval path uses an inline script ([content.js#L307-L311](https://github.com/ICWR-TEAM/Firefox-Browser-MCP/blob/2d475661406eb06788fcc505c39b72e1882c3b90/firefox-extension/content.js#L307-L311)). Both are blocked or limited by strict page CSP (the code's own comment says so, [content.js#L264-L268](https://github.com/ICWR-TEAM/Firefox-Browser-MCP/blob/2d475661406eb06788fcc505c39b72e1882c3b90/firefox-extension/content.js#L264-L268)). A Companion should use a single documented page-world mechanism and treat CSP failures as an expected result.
- Tab capture uses captureVisibleTab, which captures only the selected tab and therefore changes what the user sees ([background.js#L405-L408](https://github.com/ICWR-TEAM/Firefox-Browser-MCP/blob/2d475661406eb06788fcc505c39b72e1882c3b90/firefox-extension/background.js#L405-L408)). Firefox's tabs.captureTab is a separate call that can capture a non-selected tab without switching the selection; this checkout does not use it, so it is a design option for the Companion.
- Private windows: the code does not separate private tabs. tabs.query({}) returns them when the extension is allowed in private windows, and list_tabs includes them. The Companion must decide whether private tabs are in scope.
- The Chrome-only pieces (scripting.executeScript, chrome.action, alarms, and the MAIN-world content script entry at [manifest.json#L27-L34](https://github.com/ICWR-TEAM/Firefox-Browser-MCP/blob/2d475661406eb06788fcc505c39b72e1882c3b90/chrome-extension/manifest.json#L27-L34)) do not apply to Firefox and should not be copied.
- The bridge is a plain WebSocket server inside the MCP server process. Firefox native messaging is not used. A Companion built on native messaging does not need a listening port, which removes the unauthenticated-listener risk described above, but it changes the packaging and install steps.
- Installation: the extension is loaded as a temporary add-on for development ([README.md#L8-L20](https://github.com/ICWR-TEAM/Firefox-Browser-MCP/blob/2d475661406eb06788fcc505c39b72e1882c3b90/firefox-extension/README.md#L8-L20)). Stable Firefox needs a signed package for a permanent install; the repo's signing scripts ([package.json#L10-L11](https://github.com/ICWR-TEAM/Firefox-Browser-MCP/blob/2d475661406eb06788fcc505c39b72e1882c3b90/firefox-extension/package.json#L10-L11)) need AMO credentials and are not part of the code.
