- Summary: MCP Bridge for Firefox is a Manifest V2 Firefox add-on plus a Python MCP server. The server (FastMCP) registers 69 tools and serves them over stdio or HTTP on localhost; each call is relayed as JSON over a WebSocket (default localhost:8765) to the add-on, which carries it out with WebExtension APIs and content scripts in the tabs the agent names. The person controls it with per-category permissions, a pause switch and a blocked-site list in the add-on, and the two halves prove a shared pairing token to each other before the add-on acts.

## Architecture

- Client to server: the server runs as a stdio MCP server when started with `--stdio` ([server.py#L1368-L1414](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/server/server.py#L1368-L1414), [server.py#L1426-L1427](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/server/server.py#L1426-L1427)), otherwise as an HTTP MCP app served by uvicorn on the configured host ([server.py#L1154-L1189](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/server/server.py#L1154-L1189)). The HTTP MCP port defaults to 3000 outside tests ([server.py#L224](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/server/server.py#L224)). The host defaults to localhost ([server.py#L189](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/server/server.py#L189)), and any `--host` other than localhost or 127.0.0.1 is replaced with localhost ([server.py#L1483-L1485](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/server/server.py#L1483-L1485)).
- Server to add-on: a `websockets` server listens on host:port, default 8765 ([server.py#L1325-L1345](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/server/server.py#L1325-L1345), [server.py#L1420-L1421](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/server/server.py#L1420-L1421)). ## Permission boundaries

- Manifest permissions: tabs, tabGroups, history, bookmarks, activeTab, storage, nativeMessaging, clipboardRead, clipboardWrite, webRequest, webRequestBlocking and <all_urls> ([manifest.json#L16-L29](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/manifest.json#L16-L29)).
- Host permissions: <all_urls> only, given in the permissions list ([manifest.json#L28](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/manifest.json#L28)) and for the content script ([manifest.json#L40](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/manifest.json#L40)). The optional data-collection grant technicalAndInteraction is declared for error reports ([manifest.json#L56-L69](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/manifest.json#L56-L69), [reporting.js#L11-L13](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/reporting.js#L11-L13)).
- Per-tab or per-site grant: none. No grant step exists per tab or per site. The person sets categories (allowRead, allowInteract, allowScripts, allowUploads, allowClipboard, allowTabs, allowWindows, allowHistory, allowBookmarks, allowNetwork), a pause switch, a blocked-site list and a private-window switch ([settings.js#L11-L60](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/settings.js#L11-L60), [settings.js#L64-L81](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/settings.js#L64-L81)). The check is in [background.js#L654-L691](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/background.js#L654-L691): the category of the action is checked, then the host of the URL named in the request and the host of the tab the request names are tested against the blocked list ([settings.js#L103-L114](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/settings.js#L103-L114)). Once paused, every gated action is refused ([background.js#L660-L662](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/background.js#L660-L662)). The content script does not repeat these checks.
- Authentication: client to server, none on the MCP side. The HTTP MCP app is served without an authorization or origin check in this repository (no Authorization or Origin handling in server/); the protections named in SECURITY.md ([SECURITY.md#L51-L54](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/SECURITY.md#L51-L54)) are delegated to FastMCP, which is not in this checkout. Server to add-on: the WebSocket handshake accepts only origins matching moz-extension:// ([server.py#L69](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/server/server.py#L69), [server.py#L1341-L1343](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/server/server.py#L1341-L1343)). Web pages cannot pass that check (their origins are http or https). The websockets library performs the match; its source is not in this checkout. Pairing is an HMAC-SHA256 over the other side's nonce, keyed by the shared token ([server.py#L98-L108](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/server/server.py#L98-L108), [server.py#L478-L508](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/server/server.py#L478-L508), [background.js#L291-L296](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/background.js#L291-L296), [background.js#L298-L315](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/background.js#L298-L315)). An add-on that is not paired gets NOT_PAIRED for every request when a token exists ([background.js#L617-L623](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/background.js#L617-L623)); when no token exists anywhere it answers unpaired, as before pairing existed ([background.js#L618-L622](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/extension/background.js#L618-L622)).
- Token storage: a random 16-byte hex token in ~/.foxmcp/pairing-token, created once and set to mode 0600 on POSIX ([native_host.py#L36-L47](https://github.com/MashdorDev/mcp-bridge-for-firefox/blob/a1cb01b79a17f5b3b1f955180d4e4849137eeb89/server/native_host.py#L36-L47)). ## Firefox implementation notes

- Real input (the window-input path and the BiDi fallback, 05-F18): a stable-Firefox Companion cannot rely on the Windows window-message path or on a remote-debugging port in a person's normal profile. The BiDi route also requires the browser to be started with remote control, which the cleaner script in 05-F37 exists to undo. Plan for scripted events, or a separate mechanism, and say so in the product.
- Script execution in the page's realm (05-F15, page_realm) and the file-input hook (content.js#L1018-L1052, 05-F19) use wrappedJSObject, exportFunction and cloneInto. These are Firefox-only Xray facilities; they work in a Firefox WebExtension but must be re-verified on the target Firefox 160 build.
- Native messaging host (05-F31): the host is a per-user Python program registered through a manifest and, on Windows, an HKCU registry value. It works without admin rights but is a second install component; the Companion can avoid it with its own pairing scheme.
- Blocking webRequest with filterResponseData (05-F23): depends on the blocking listener form of the webRequest API. Confirm support in the Manifest V3 path before choosing V3.
- Tab group APIs (05-F04) need Firefox 138 and 139; both are earlier than Firefox 160.
- Thunderbird (05-F07, 05-F08): uses a privileged experiment API and Thunderbird-only namespaces. Not applicable to stable Firefox.
- Unsigned install (05-F33, scripts/install-xpi.sh): the user.js route is not a supported path on stable Firefox; signed packages are required.
- Clipboard image write (browser.clipboard.setImageData) and paste (05-F20): paste into a non-textarea uses a temporary textarea and execCommand('paste'), a Firefox-specific limit recorded in the code.
- Predefined scripts (05-F21): run a local program from the server side. The Companion, which has no such server, would need its own policy for any local program.
- Error reports (05-F34): rely on the data-collection permission API; the opt-in grant must be in place before any report is sent.
