- Summary: Browser Control MCP is a Firefox Manifest V2 add-on plus a Node.js stdio MCP server with 9 tools for tab management, history, page text, find-and-highlight and tab screenshots. The server forwards each call as an HMAC-signed JSON message over a localhost WebSocket to the add-on, which carries it out with tabs, history and activeTab APIs. Page text and find need a per-site permission that Firefox asks for, and screenshots need a click on the toolbar button for each tab.

## Architecture

- Client to server: MCP over stdio only, using StdioServerTransport; the process exits when stdin closes ([mcp-server/server.ts#L290-L300]([server.ts#L290-L300](https://github.com/eyalzh/browser-control-mcp/blob/e53f0e50e2778543d2c2b5dadbe565be82920fbf/mcp-server/server.ts#L290-L300))). There is no HTTP transport.
- Server to add-on: a `ws` WebSocket server on each of 127.0.0.1 and ::1 at the configured port, 8089 by default, or 0.0.0.0 when CONTAINERIZED is set ([mcp-server/browser-api.ts#L48-L63]([browser-api.ts#L48-L63](https://github.com/eyalzh/browser-control-mcp/blob/e53f0e50e2778543d2c2b5dadbe565be82920fbf/mcp-server/browser-api.ts#L48-L63)), [mcp-server/browser-api.ts#L282-L286]([browser-api.ts#L282-L286](https://github.com/eyalzh/browser-control-mcp/blob/e53f0e50e2778543d2c2b5dadbe565be82920fbf/mcp-server/browser-api.ts#L282-L286))). The server takes one port only: if it is busy, init throws ([mcp-server/browser-api.ts#L48-L50]([browser-api.ts#L48-L50](https://github.com/eyalzh/browser-control-mcp/blob/e53f0e50e2778543d2c2b5dadbe565be82920fbf/mcp-server/browser-api.ts#L48-L50))).
- Add-on to server: one client connects to ws://localhost:port and retries every two seconds ([firefox-extension/client.ts#L23-L26]([client.ts#L23-L26](https://github.com/eyalzh/browser-control-mcp/blob/e53f0e50e2778543d2c2b5dadbe565be82920fbf/firefox-extension/client.ts#L23-L26)), [firefox-extension/client.ts#L78-L92]([client.ts#L78-L92](https://github.com/eyalzh/browser-control-mcp/blob/e53f0e50e2778543d2c2b5dadbe565be82920fbf/firefox-extension/client.ts#L78-L92))). ## Firefox implementation notes

- The active-tab screenshot design (18-F09, 18-F10) is the most Firefox-native part: it uses activeTab, which Firefox ties to a user gesture on the toolbar button and drops on navigation. A stable-Firefox Companion can reuse it and should check the drop-on-navigation behaviour on Firefox 160.
- Per-site permissions (18-F05, 18-F07, 18-F11) use optional host permissions requested one origin at a time, which is the Firefox-enforced grant model. A Companion can use the same pattern for per-site consent.
- find and highlight (18-F07) depends on the optional "find" permission and the browser.find API. Both are Firefox-specific, and the permission is requested at run time.
- Tab groups (18-F08) depend on browser.tabGroups, which needs Firefox 139 or later.
- The local WebSocket server with a shared secret (18-F14) runs in a separate Node process, which is not a stable-Firefox feature. A Companion can drop it for a native messaging host or a different local transport, and must not rely on an Origin check unless it is enforced by a verified transport.
- The Companion must not use a single-slot connection model, which here lets the newest socket take all commands.
