- Host permissions: not stated in the sources.
- Per-tab or per-site grant: the user approves a site when Claude Code asks, and can allow all actions on that site for the session ; the tools act only on tabs in the session's MCP tab group . No code was reviewed, so enforcement is as described by the sources only.
- Authentication: `/login` is required, and an API key or long-lived token keeps Chrome integration off ; the extension must be signed in to the same claude.ai organization as Claude Code . Token storage, origin checks and bind address: not stated in the sources.
- Sensitive-action gating: the product page says purchases, financial actions and anything irreversible wait for the user, without listing them ; plan mode prompts before a GIF recording or a new tab ; `action_summary` describes each mutating action to the user and `read_network_requests` shows auth values as REDACTED ; file upload refuses files the session may not read, credential-named files and hard-linked files .
- Gaps: the product page says Claude "asks before sensitive actions" but does not define which actions count . The docs say that in auto mode the extension can skip its own per-site check for a call the classifier approves, unless permission rules deny a site ; this is a risky default for any site not covered by a deny rule.
